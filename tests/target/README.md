# crackme — подопытная программа для ручной проверки MCP-инструментов

## Зачем это нужно

`crackme.exe` — маленькая консольная программа-мишень. Она не проверяет
работу самого плагина x64dbg-mcp автоматически — она даёт **заранее
известные правильные ответы**, чтобы при ручной проверке инструмента MCP
(чтение памяти, поиск строк, поиск по сигнатуре, список потоков,
дизассемблирование, патч и т.д.) можно было сразу сказать: инструмент
ответил правильно или соврал.

Программа при старте печатает опорные значения (PID, базовый адрес
модуля, адреса ключевых мишеней) — их и нужно сверять с ответами
инструментов.

## Сборка

Цель `crackme` не собирается при обычной сборке плагина — только по
явному флагу:

```
cmake -B build64 -A x64 -DX64DBG_MCP_BUILD_TARGET=ON
cmake --build build64 --config Release --target crackme
```

Готовый файл окажется в `build64\Release\crackme.exe`.

## Таблица мишеней

| Мишень | Как проверить | Правильный ответ |
| --- | --- | --- |
| ASCII-строка `X64DBG_MCP_TEST_ASCII_STRING` | Поиск строк / чтение памяти по адресу из вывода | Строка читается ровно как `X64DBG_MCP_TEST_ASCII_STRING` |
| Wide-строка `X64DBG_MCP_TEST_WIDE_STRING` | Поиск wide-строк / чтение памяти как UTF-16 | Строка читается ровно как `X64DBG_MCP_TEST_WIDE_STRING` |
| Маркер `g_pattern_marker` = `DE AD BE EF CA FE BA BE 12 34 56 78 9A BC DE F0` | Поиск по сигнатуре (byte pattern search) | Найденный адрес совпадает с адресом `g_pattern_marker`, напечатанным при старте |
| `check_password` | Список экспортов / поиск символа по имени, дизассемблирование функции | Адрес функции совпадает с напечатанным при старте; внутри виден условный переход после `strcmp` |
| `compute_checksum` | Дизассемблирование функции, разбор цикла | Виден цикл суммирования байтов буфера |
| `xor_decrypt` | Дизассемблирование функции | Виден цикл `XOR` над буфером |
| `target_function(a, b)` | Установка точки останова, чтение/запись регистров и аргументов, изменение результата | Возвращает `a + b`; изменив значение аргумента или регистра результата, видно изменение возврата |
| `g_magic` (стартовое значение `0x1337`) | Чтение памяти по адресу; запись памяти | Значение в выводе программы (`g_magic=0x...`) сразу меняется после записи нового значения инструментом |
| `g_counter` | Чтение памяти в цикле | Значение растёт на 1 каждую итерацию (~500 мс) |
| Импорт `Sleep` | Точка останова на API-функции | Останов срабатывает каждую итерацию основного цикла (~500 мс) и каждые ~750 мс в рабочем потоке |
| Импорт `GetTickCount`, `CreateFileW` | Список импортов / перекрёстные ссылки на API | Обе функции присутствуют в таблице импорта, вызываются один раз при старте |
| Рабочий поток (`CreateThread`) | Список потоков, чтение регистров чужого потока | В списке потоков виден второй поток; его счётчик (`g_thread_counter`, не выводится в консоль, но растёт в памяти) увеличивается с периодом ~750 мс — отличным от главного потока |
| PID, база модуля | Присоединение отладчика к процессу | PID и база в отладчике совпадают с напечатанными при старте |

## Патч: DENIED → GRANTED

Основной цикл всегда вызывает `check_password("wrongpass")` — заведомо
неверный пароль, поэтому в выводе постоянно видно `access=DENIED`.

Чтобы получить `access=GRANTED`, нужно найти в `check_password` условный
переход, который следует за вызовом `strcmp` (`je`/`jne` после сравнения
результата с нулём), и инвертировать его (например, `jne` → `je`, либо
заменить переход на безусловный `jmp`, либо через NOP убрать сам переход
так, чтобы всегда выполнялась ветка `return 1;`).

Как убедиться, что патч подействовал: после изменения байта(ов) в памяти
процесса, не останавливая программу, дождаться следующей строки вывода —
в ней должно появиться `access=GRANTED` вместо `access=DENIED`.

## Важно

Собранный `crackme.exe` намеренно не хранится в репозитории — он
собирается локально командой выше и является рабочим (одноразовым)
артефактом для ручной проверки.
